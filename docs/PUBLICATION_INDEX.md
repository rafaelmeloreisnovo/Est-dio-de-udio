# Publication Index — document products

The documentation is published as a family rather than one oversized manual.

## Product layer

1. **Product Overview** — concise value, scope and boundaries.
2. **User Guide** — operation and workflows.
3. **Capability Matrix** — implemented / pending / evidence state.
4. **FAQ** — common interpretation questions.

## Technical layer

5. **Developer Guide** — code routes and contribution workflow.
6. **Audio Manifold Contract** — architecture and scientific boundary.
7. **ZRF/CFR Format** — binary reference.
8. **μ∆ Vibration V1** — sensor semantics.
9. **Hardware Test Protocol** — repeatable physical testing.

## Assurance layer

10. **Installation Validation** — prove which APK is installed.
11. **Verification & Evidence** — receipts, hashes and claims.
12. **Release Readiness** — release gates.
13. **Security Boundaries** — trust model and limitations.

## Agent layer

Scoped `AGENTS.md` files define how humans and IAs should work in each repository subtree.

## Public communication rule

A public document may be shorter than the technical source, but never stronger.
The capability matrix is the preferred source for feature-state wording.
